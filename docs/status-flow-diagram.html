3 JavaScript Edit-Modal Pre-fill history.html · lines 604–640

When the Edit button is clicked, JS reads data-status from the button and normalizes synonyms:

var status = btn.dataset.status || 'SCHEDULED'; var statusUpper = status.toUpperCase(); // Synonym normalization if (statusUpper === 'PENDING') statusUpper = 'SCHEDULED'; if (statusUpper === 'COMPLETE') statusUpper = 'COMPLETED'; if (statusUpper === 'CANCELLED') statusUpper = 'CANCELED'; editStatusSelect.value = statusUpper; // pre-selects <option>
Why synonyms? Legacy data or manual DB edits might contain PENDING, COMPLETE, or CANCELLED. The JS mapping ensures they match dropdown values.

6 Server-Side Normalization app.py · lines ~1280–1290 / ~1427–1440

Two layers of processing ensure consistent storage:

String Cleaning

  • .strip() — remove whitespace
  • .upper() — force UPPERCASE
  • Already uppercase from <option> values, but this catches edge cases

Synonym Mapping

  • PENDING → SCHEDULED
  • COMPLETE → COMPLETED
  • CANCELLED → CANCELED
  • IN PROGRESS → PLAYING
status = request.form.get("status", "SCHEDULED").strip().upper() # Synonym mapping STATUS_MAP = {"PENDING": "SCHEDULED", "COMPLETE": "COMPLETED", "CANCELLED": "CANCELED", "IN PROGRESS": "PLAYING"} status = STATUS_MAP.get(status, status) # Final value: "COMPLETED"
